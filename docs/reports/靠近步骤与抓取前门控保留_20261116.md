# 合并图保留靠近及抓取前门控（2026-11-16）

用户补充：靠近目标与抓取是独立步骤。第一次靠近后，抓取条件不满足时不能抓取，应先完成清障等准备；条件变化后再次靠近，再检查抓取条件，成立才进入抓取。不同状态的靠近不能合并成同一个循环节点。结束前仍不增加门控或完成验证。

## 实现

- 主图契约升级为 model_success_graph.v3，提示词对未来合并图持续生效。每个操作的 action_role 由部署模型声明，程序不按动作名称或文件名猜角色。
- 模型必须逐来源输出 approach_review，按路径顺序列出所有靠近 occurrence 及其后续抓取条件门控；靠近节点保留 state_context、七元组与源证据。
- 校验不允许把靠近隐藏在抓取的 R 中；每个抓取必须通过抓取前置门控的 T 分支，F 分支不能直接抓取，完成准备后必须保留新的靠近及新的条件门控。
- 两次靠近使用不同节点 ID，并沿用无循环、来源路径不串接的检查。清障前后的目标接近不能因为语义同名而丢掉出现次数。
- 门控 truth 与分支 gate_outcome 分开：前者表示模型对证据的判断，后者表示图要求的通行条件。truth=U 不自动变成 T/F，图不绑定执行器。
- 确认靠近出现次数、时间、对象、状态、门控谓词与七元组，均由现有8032的 qwen3.8-27b 分析。未定位时间使用 null，程序不补猜。
- 成功流程学习、失败抓取留反例、七元组和结束前无门控的政策继续生效。单视频历史数据及原视频保留。

工作台新增靠近状态和逐来源出现次数核对；图与主图JSON仍直接来自部署模型，宿主只附加媒体链接与排版。

生成流程现在明确分为：视频实例识别 → 部署模型的语义节点对齐 → 局部正反例复核。节点对齐只读取已保存的部署模型实例结果与旧成功图候选，不重复看视频；它必须保留每个来源的靠近出现次数和原始成败判断，并真正共享同目标抓取节点。物体颜色、支撑位置等跨视频实例差异不能成为将所有语义步骤分开绘制的理由。同一路径内的重复靠近仍须分开。这些对齐结论继续由模型给出，程序没有语义合并降级路径。

## 用户纠正：抓笔合并图只能从靠近开始

本批次 graph_requirements.json 明确要求开始只有一条出边，唯一后继角色为 approach_target；禁止“开始→清障/移动障碍物”以及额外的清障入口。入口政策只作用于显式指定的任务，不擅自套用于其他视频任务。条件不成立时清障，之后再次靠近和检查条件，成立再抓取；结束前仍无门控。

这是用户指定的归纳任务流程，不能把原视频事件顺序原封不动当作学习图入口。若入口规则要求补充某来源没有观测到的初始靠近，必须由Qwen标为rule_only_occurrences、observed=false；源引用时间为null，不给伪造证据，不增加实际观察到的靠近次数。原视频事实与时间保持在实例模型记录中。

只有入口政策、提示词变化时，重新调用语义合并模型，不重跑视频实例分析。记录保存需求文件SHA，离线导出会拒绝过期图。程序只校验模型是否遵守用户政策，不移动节点或补写业务图。

可复用的显式政策文件是 tasks/pick_pen_graph_requirements.json，例如在已授权8032的服务器study环境运行：

python -B tools/export_cross_video_workbench.py --out output/意图拿笔 --analyze --allow-model-service --graph-requirements tasks/pick_pen_graph_requirements.json
~~~
