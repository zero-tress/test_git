# 跨视频归纳图与单视频展示方式对齐（2026-11-16）

本次按用户参考图修改 output/意图拿笔 的跨视频操作图。业务归纳与节点、门控、七元组、实现方式和支路映射由现有8032的 qwen3.8-27b 生成，宿主没有按动作名称合并节点的降级路径。

## 业务结果与展示边界

Qwen输出的最终图为8个节点：开始、初始靠近、初始抓取条件、共享清障、准备后靠近、准备后抓取条件、共享抓取、结束。清障源实例的差异保留在共享七元组、R和sources中，不再画成按视频分开的两个清障节点。两次靠近是同一路径中的不同状态位置，仍分别保留。

开始唯一后继为靠近。条件不满足的支路经过清障、再次靠近及第二个抓取条件检查，再汇入共享抓取。结束前不增加门控或完成验证。原始观测、用户规则补充步骤及失败反例仍分别保存，规则步骤不会获得虚构视频时间。

图面只显示模型提供的display_label，不显示来源编号或视频实例名称；来源与证据放进可折叠明细。清障的归类由模型完成；绘图程序只依据已经给出的拓扑和gate_outcome选择主线与上方支路位置，既不改变节点/边，也不决定视频内容或条件真值。

## 复用单视频方式

- SVG复用 video2op/render.py 的GS尺寸、字体、线条样式与颜色，操作画圆、条件画菱形。跨视频分支几何由 cross_video_render.py 排版；不调用单视频的动作名称归类/缩写逻辑，文字直接使用模型给出的display_label。
- HTML直接复用 video2op/workbench.py 的CSS和JS，沿用左侧操作图、右侧详情、点击操作看七元组、点击门控看条件、Esc取消选择的方式。模板在生成时已写入全部详情。
- 七元组X、O、C_pre、C_const、E、C_post、R完整保留。E的四个评价字段、R候选实现与源证据不因图面简化而丢失。图面不显示T/F/U，模型状态在门控详情中展示。
- 独立正反例学习、归纳说明及模型追溯收进折叠区，保持主图简洁。SVG和HTML内联主图来自同一个绘图函数。

## 文件与调用

入口为 output/意图拿笔/workbench.html 和 operations.svg；原始模型图为 success_process_model/result.json，语义合并调用记录在 semantic_alignment_model/。
