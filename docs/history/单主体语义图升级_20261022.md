# 单执行主体语义图升级（2026-10-22）

## 主图行为

一个操作节点只有一个执行主体。X.subject 直接写“右臂”“右手”等，X.parts 只含同一个主体。
开始/结束为控制边界，不是多主体操作节点。

燕麦杯取放图现在直接展示六个操作：

    开始 -> 靠近（臂） --+
          -> 打开（手） --+-> AND门控 -> 抓取（手） -> 移动（臂） -> 释放（手） -> 撤回（臂）

靠近和打开的并行是语义许可，不能由示范视频恰好先后发生而改成串行。
底层设备的运动/夹爪互斥在下一层映射时处理，不反向合并本层节点。
抬升、搬运、下降在同一主体、同一物体、同一握持周期内可收敛为一个“移动”语义节点，
原始动作与来源仍可追溯。左右臂、左右手分别处理。

抓取成功后，握持状态延续至释放开始前，以 maintain_until 关系表示，
until_event=target_starts，且关联条件谓词登记为 kind=hold / hold_scope=cross_node。
主图绘制黑色虚线持续关系，箭头落在释放前的门控，点击仍可查看握持关系含义。不新增“保持”动作节点。

## 图形与交互

沿用原圆形操作节点、菱形门控、黑色连线。
开始分出靠近与打开两支，两支汇入同一个门控。
操作节点与门控文字均水平、垂直居中。门控菱形宽高缩为此前的 3/4（165 × 102）。
释放与靠近为互斥的语义阶段：上一轮释放完成后才能靠近下一目标；
下一轮的靠近与打开仍可并行。
主图不显示示范秒数；点击节点查看七元组、单主体、来源、推断与原始证据。
已满足的打开状态不伪装成视频里发生过一次独立打开动作。
无独立动作时间的语义目标，详情明确显示未知，不以 0 秒代替。
节点、门控和持续关系均支持点击，Esc 取消选择。

## 数据和边界

新增 video2op/single_actor.py，构建单主体节点、逻辑依赖、并行层、持续关系和证据审查。
原复合任务七元组存入 task_nodes_source；原分析保留 source_analysis。
语义节点通过 source_node_ids、source_skill_tuples、atomic_refs 保留映射来源。
原视频动作、执行主体、实际时间不被改写。
重复离线重建幂等；多个抓取周期不会在尚持有上一物体时提前打开下一次抓取的手。

R 是语义候选方式，不强制绑定机器人行为树模板，不选择执行策略，不生成设备命令。
本地语义契约为 video2op/schemas/semantic_learning_graph.schema.yaml。
action_catalog.json 明确功能、单主体范围和后续可参考的原子能力：
靠近/移动/撤回对应臂运动；打开/抓取/释放对应手操作。
控制接口信息不限制本层的语义并行含义。

语义后置是目标，不是事实。失败状态不会被改成成功；缺乏位姿或全过程握持证据时保持未知。
原始失败与状态证据、确定性推断和已满足的状态目标分别标注。
