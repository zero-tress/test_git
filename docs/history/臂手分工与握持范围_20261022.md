# 臂手分工、握持范围与主图时间显示（2026-10-22）

## 实际分工

新模块 video2op/arm_hand.py：
- 臂：靠近、移动、带载移动、撤回。抓握前臂靠近，是为手提供可抓取位置。
- 手：张开、抓握、释放，分别对应 OperateGripper 的 MODE_SET_WIDTH / MODE_GRASP / MODE_RELEASE。
- 空间移动对应 move_chain_client（PlanMotion -> ExecuteWaypointPlan）。
- grasp_chain_client 是臂手协作的复合短链，其内部运动不能全部记到手上。
- 整体仍只用于垂直上升/下降与水平移动。

模型若把“手移动杯子”作为空间运动、把“臂抓握”作为夹爪动作，提取校验会要求修正。
离线读取旧结果时只标记分工疑点，不静默更改观测执行主体。
手臂被遮挡时记录不确定性，不凭手的运动虚构臂的观测。

动作及任务新增 functional_role / functional_roles；靠近的目标与理由通过 reach_requirements 表达。
“观察到靠近”和“手已处于可抓位姿”分开校验。状态未知时仅提出条件式臂靠近候选，无虚构时间。

## 握持的精确范围

持续约束的有效区间为：

    [抓握成功, 释放动作开始)

不从抓取节点准备阶段要求已经握住杯子；不在接触桌面的瞬间提前结束；不覆盖释放动作过程。
释放开始允许手张开，释放完成才确认抓持关系解除。释放前的支撑条件仍需成立。

复合“放置”节点含臂下降及手释放时，约束仅覆盖释放开始之前的内部阶段。
纯释放节点和释放后的撤回节点不要求继续抓紧。没有观察到释放时，保持开放终点并提示待确认。

数据以事件引用和 scoped_grip_constraints 表达，不生成保持动作节点。
旧约束原文保留在 constraint_revisions，修正后的 C_const 明确写生效起止。
仅观察到抓握起点不证明全过程持续成功；滑落等反证单独标记，不把“不滑落”误当成滑落。
多个抓取周期、左右手分别处理。
