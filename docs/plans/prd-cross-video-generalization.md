# 跨视频统计归纳：后续任务与实施方案

## 1. 目标与范围

本轮核心目标：在已有单视频操作图基础上，形成可审阅、可追溯的跨视频通用语义操作图，明确验证两个方面：

1. 支路合并：对同一任务或局部目标的不同案例进行结构对齐，保留共同部分、差异路径及其条件。
2. 功能合并：把满足同一语义目标和后置效果的不同实现，归纳为语义技能的候选实现集合 R。

分类与意图对齐是上述归纳的输入。分类结果、视频片段数量、技能数量及 R 的数量，均不能单独证明两种合并已经正确完成。

负责范围沿用本次讨论的图①主流程①—⑦，以及图②语义技能表达和待绑定接口。用户明确排除相机整体晃动补偿、光流/帧差/边缘与运动区域活动分数计算，以及底部 A/B/C 作为独立工作包。①—⑦输出中原本需要的技能字段、约束和评价规则继续保留。

机器人控制、原子能力/行为子树的实际绑定和反馈闭环继续作为执行侧边界。新版图中的执行因果库记录为外部依赖：本轮明确所需证据与输入输出接口，其建设归属尚待明确，不将现有条件统计表述为已经接通执行因果库。

## 3. 工作包与验收标准

### T0：统一任务、技能与效果定义

目的：先确定哪些案例可以比较，避免同名误合并和粒度混乱。

任务：

- 分清整段任务、任务中的子目标、语义技能、具体动作及实现路径。
- 每个语义技能定义目的、对象角色、后置效果和完成评价规则。
- 说明“抓取”指建立稳定握持，还是包含准备步骤的更大任务范围；前置清障可以作为父任务中的条件准备，不能无差别并入每一个抓握原子动作。
- 以效果区分“移除障碍物”和“解除接近阻碍”。后者若定义为目标可达，可以容纳绕行、等待动态障碍离开等候选；前者要求障碍物被移除，不能直接收纳这些实现。
- 已有目标合同与新增抽象定义都标明来源；不把人工定义的技能名称当作系统自主发现的成果。

交付：技能与目标定义表、合并/不合并的示例清单。

验收：用于首轮归纳的每个案例都有明确的目标、对象角色与抽象层级；存在歧义的案例标记待审阅，并保留原因。

### T1：建立带上下文的视频技能证据单元

目的：把分类后的案例转成可用于路径和功能比较的证据。

任务：

- 为每个实例记录原视频路径及哈希、时间范围、相关动作/图节点、对象绑定、前后状态、局部结果及证据引用。
- 同时保留父任务与相邻操作关系，避免只截到抓握瞬间，丢失清障、再次靠近等上下文。
- 支持技能嵌套、时间重叠及必要的多个区间，不强制把视频切成互不重叠的一排片段。
- 默认用原视频加时间索引。独立小视频作为可选审阅材料，保留源时间映射；裁剪本身不作为学习完成的标准。
- 原始模型观察、给定任务、人工审阅分别保存。整段任务的失败不能直接覆盖其中成功的局部抓取。

交付：技能实例与视频证据索引。

验收：每个纳入合并的实例可定位到实际视频证据；观察不清、缺少前后画面或对象身份冲突的情况有明确状态。

### T2：完善支路合并

目的：从多个案例归纳共同结构与可选路径，同时保留路径之间的约束。

实施方案：

1. 先按目标、对象角色和粒度筛选可比较案例。
2. 以目标效果、角色和前后状态作为对齐锚点，再比较动作与时序关系；动作名称和出现次数只作为辅助特征。
3. 合并有依据的共同节点和关系，保留差异操作及其分支归属。
4. 分支记录候选条件、证据来源、审阅状态；证据不足时保持未知。
5. 校验完整路径及变量绑定，防止只拼接边而组合出任何原案例都不支持的新路径。
6. 核对每个R中的全部实例；动作串相同但时序关系、对象绑定或效果不同的成员要拆分或保留差异，不能只用一个代表实例替整组作结构判断。

首轮结构示例：

```text
案例甲：开始 → 靠近 → 抓取
案例乙：开始 → 靠近 → 清障 → 再次靠近 → 抓取

通用图：保留直接抓取路径与先清障路径；
        “目标可抓取/存在阻碍”等选择条件由案例证据支持。
```

同名的两次靠近、不同对象的抓取、不同手的协同关系都要保持对应关系。顺序、并行与交替分别处理，不因展示方便把所有结构压成单一序列。首版保留有限展开的重复步骤，不凭空推导循环策略。

交付：合并操作图、原实例到通用节点的映射、完整路径归属、分支条件和冲突报告。

验收：

- 每条纳入归纳的源路径均可按其映射和分支归属重建。
- 直接抓取路径不被错误强制加上清障步骤。
- 再次靠近不被错误合成自环或丢失。
- 没有无证据的跨支路拼接、对象替换或时序变化。
- 被拒绝、发生冲突或尚待审阅的案例单列，并计入覆盖统计。
- 上述示例先用于规则验证；只有实际视频支持时才计入实视频学习成果。

### T3：完善功能合并与候选实现集合 R

目的：用同一个语义效果连接不同做法，并保留各自的适用边界。

实施方案：

1. 比较目标合同、对象角色和后置效果的兼容性；仅名称相同或文字相似不能直接合并。
2. 对满足同一语义目标的实现建立 R；相同功能下可保留动作、过程、时序和能力要求不同的多个实现。
3. 每个R保存实现子图引用、角色绑定、专属前置/过程约束、能力要求、评价规则及支持/反例证据。
4. 分离同一实现内部的路径变体与实现间替代关系，并用明确的引用关联二者，避免重复计数和混淆层级。
5. 公共条件只有获得跨实现证据支持时才提升到技能层；实现专属条件继续留在各R之内。

技能层保持目的与角色的统一表达；具体载体通过能力要求筛选可用R。不能从统一语义表达推断所有载体都可以执行所有R。

交付：功能合并决策、更新的技能七元组、R与实现子图的对应关系。

验收：

- 纳入同一技能的每个R均有可解释的目标与效果对应依据。
- 不同做法可以被归为同功能；同名但效果不同的操作被分开或标记冲突。
- 每个R可追溯到实际案例；无视频支持的绕行、等待等仅列作设计候选，不计入已学会实现。
- 原子能力、检测器和行为子树未绑定的状态继续如实保留。

### T4：补充分支与功能合并所需的条件证据

目的：让通用图说明何时适用，并使合并结论可以被审阅。

任务：

- 复核阻碍是否存在、目标是否可达、抓握是否稳定以及技能后置效果是否成立。
- 使用成功、失败、未执行与不确定案例做对照，分别保留任务级和局部技能结果。
- 分开记录条件真假T/F/U、结果四态、模型观察、人工审阅和因果证据等级。
- 为分支条件和R的适用性分别报告支持、冲突和缺口；观察相关性不自动升级为普遍因果规则。
- 复杂时序、多意图与复合任务只在与本轮案例有关时补验证；没有对应素材时保留缺口，不要求模型必须产生预定模式或排序反转。

交付：分支/R条件证据表、逐命题审阅表、待补素材清单。

验收：每个已确认条件有对应的具体命题和证据；无法确认的条件保持候选或未知；未执行不被当作条件导致失败的反例。

### T5：建立针对两种合并的验收

目的：分别验证软件机制、真实案例语义和未见案例解释能力。

三个验证层级：

1. 确定性机制检查：直接/绕行支路、重复动作、不同对象、并行关系、同效果不同路径、同名不同效果，以及禁止的跨支路拼接。构造样例仅作为软件测试，不冒充实视频证据。
2. 真实案例审阅：选择现有视频里有证据的对照组，审阅目标、源路径、节点映射、R成员及条件；原模型输出保持可追溯。
3. 冻结知识后的留出解释：报告已有路径可解释、需新支路、需新R、目标不匹配或证据不足。已有02/06/14继续作为历史留出回归，其反复使用不能代替新的独立泛化证据；若据此调参，记录调参过程并另留未用于调参的样本。

记录指标：纳入与待审实例数、源路径重建率、人工审阅的错误合并/拆分、同效果不同实现覆盖、分支/R条件支持程度、留出解释分类和全部缺口。

验收：首批审阅案例中已发现的错误合并均得到修正或隔离；纳入合并的源路径全部可重建；失败、未知和排除案例完整报告；回归测试通过。素材不足时报告机制完成和实证缺口，不预填全部通过。

### T6：交付可复核结果并更新完成度

目的：让使用者能从合并结果返回原始依据。

交付内容：

- 技能实例/片段索引与任务上下文。
- 支路合并图、节点映射、路径归属和条件证据。
- 功能合并后的七元组、R及实现子图。
- 正反例审阅、合并决策及留出解释报告。
- 新验收账本：逐项区分已有能力、本轮新增、机制通过、实视频验证、待审与范围外。

审阅方式：沿用现有离线报告能力，提供“原案例路径—合并图—R—视频证据”的关联查看。本轮不擅自修改知识工作台的数据库表结构或技能前端。

验收：用户可以对每个分支或R回答“为什么合并、来自哪些视频、哪些条件有证据、哪些仍未知”。知识数量变化如实说明，不以保持原有6类或42个R为成功目标。
